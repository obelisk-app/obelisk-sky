# AGENTS.md: Obelisk Sky

Obelisk Sky (https://sky.obelisk.ar) is a 3D floating-island village that is also a real Obelisk client. Every NIP-29 channel on the selected relay is a house; people walk to the house of the channel they post in, walk over to whoever they reply to, sit and drink mate, train in the park, join voice calls and play games. You log in with your own Nostr key; the server holds no keys and fetches nothing from relays. Everything happens in the browser. Logged out, or with an account the relay hasn't admitted, you get the guest island: a scripted village, local only (below).

This is the one instruction file for every agent here; `CLAUDE.md` only imports it. When the code moves, fix the sentence here in the same change.

## Stack

- **Three.js 0.180 + Vite 7 + TypeScript**, no framework for the world UI (plain DOM in `client/src/ui/`). React only for islands that re-host obelisk-dex components (login modal, chat message bodies, the channel message bar, the profile editor).
- **Relays:** `@nostr-wot/relay/hub` RelayHub, set up like obelisk-dex's page hub. Signers from `@nostr-wot/signers`, profiles from `@nostr-wot/data`, login widget `@nostr-wot/ui`.
- **Vitest** (+ jsdom and Testing Library for the React islands).
- **Server:** `server/index.ts` is a tiny Node HTTP server. It serves `dist/client` (the landing page at `/`, the village at `/app`; old `/?relay=` and `/?time=` links get a 302 to `/app`), `/healthz`, `/api/link-preview` (the vendored obelisk-dex OpenGraph unfurler, with its SSRF guards) and `/api/avatar` (`server/avatarProxy.ts`: a profile picture whose host sends no CORS, for the WebGL badge; same SSRF guards, raster images only, no SVG). Nothing else; never add relay access or keys to it.

## Commands

```bash
npm install
npx vite client --port 5174 --host 127.0.0.1   # dev (also: npm run dev:client)
npx tsc -p tsconfig.json                        # typecheck (vite build does NOT typecheck)
npm test                                        # vitest run
npm run build                                   # client to dist/client, server to dist/server.js
pm2 restart obelisk-sky                         # deploy: the live site serves this directory's dist on :3024
npm run vendor                                  # re-snapshot obelisk-dex src (see below), then copy-brand and make-icons
node scripts/make-icons.mjs                     # favicon.ico, icon-192/512, maskable, apple-touch from brand/sky-mark-flat.svg
node scripts/build-people.mjs                   # rebuild character assets from _dl/quaternius
node scripts/make-og.mjs <1200x630.png>         # redraw the link-preview card client/public/og.jpg (text kept in the centre square: WhatsApp crops to it; bump ?v=)
node scripts/guest-npcs.mjs                     # re-resolve the guest island's villagers (NIP-05 / npub, kind 0 checked on public relays; read only) into client/src/guest/npcs.json
```

Deploy = `npm run build && pm2 restart obelisk-sky`, then check through the tunnel: `/`, `/app`, `/healthz`, the village's `assets/app-*.js`, and any new asset you added (`curl -I https://sky.obelisk.ar/...`). Run typecheck and the full test suite before every deploy.

## The seam with obelisk-dex

Obelisk-dex code is imported from `vendor/obelisk` as `@/...` (Vite alias and tsconfig `paths`). Modules that would reach the app's bridge, next-intl or Next routing are swapped by `SHIMS` in `client/vite.config.ts`, mirrored in `tsconfig.json` `paths` (`next-intl`, `@/i18n/navigation`, `@/hooks/session/useSession`, clipboard, blossom, `@/services/nostr-bridge`, `@/services/wot/engine`, the media library modal). `vitest.config.ts` uses the same `SHIMS`.

- Re-vendor deliberately (`npm run vendor`), never by editing files under `vendor/`. After re-vendoring, re-run typecheck and tests: shims may need new exports.
- Sky has its own mark (a white cloud with the Obelisk rising out of it, `client/public/brand/sky-mark*.svg`) and palette (`--sky`, `--cloud`, `--ink` in `styles.css`; the landing page and the loading screen, gate and brand pill use it, the in-app panels stay dark). `copy-brand.mjs` no longer copies obelisk-dex's icons; `make-icons.mjs` draws sky's.
- `scripts/copy-brand.mjs` copies `obelisk.stl`, writes the manifest (`start_url: /app`) and generates `client/src/obelisk.generated.css` from the vendored `globals.css` (Tailwind v4 `@source` globs for the components sky renders). Do not edit the generated file.
- **The channel message bar** (`chat/composer/`, mounted by `ui/chatPanel.ts` into `.chat-bar`) is obelisk-dex's composer: `SkyComposer.tsx` is its `ChatComposer` skin (reply bar, attachment menu, emoji/GIF/sticker picker, @-mention and slash pickers, scaffold, voice note, send) with a textarea (Shift+Enter is a new line) and the picker as a sheet in the panel's flow. `useSkyComposer.ts` is `useChannelComposer` with sky's data: mention candidates from `deps.people` (every channel's members and posters, people in the village), sends through `deps.send(group, text, reply, tags)` (custom emoji / sticker / voice-note tags from dex's `outgoingTags`; a failed send keeps the draft), bot commands from dex's `useBotCommands` (kind 30078 `obelisk:bot-commands:<relay>`, inserting the bot's own trigger such as `!milugar`), the operator's emoji set (kind 30030 `obelisk:emojis:<relay>`) into dex's chat store. `/play` opens sky's game table; `/zap` opens sky's zap sheet (below). Uploads use the blossom shim. Sky keeps no media favourites: `nostrActions.saveMediaFavorites` throws and `styles.css` hides the picker's favourite and "Create" controls.
- **The profile editor** (`profile/`): the header's account pill opens a menu, Edit profile / Your look (the look creator). Edit profile is sky's own face (`profile/SkyProfileForm.tsx`, a cloud card in sky's palette: banner and picture as previews you tap to change or remove, no URL boxes; your name, NIP-05 and npub to copy; name, about, lightning address, NIP-05, website) on dex's editor logic (`useProfileEditorForm`, `useProfileAppearanceEditor`: images checked, previewed, uploaded only on Save); × or Esc closes, it scrolls inside on a phone held sideways. The look creator also closes from its ×, Esc, or the account pill (`closeCreator`). Its save is the session shim's `updateProfile` (dex's `updateSessionProfile`: picked images go up through the blossom shim first, dropped if the account changes) and then `SkyHost.editProfile` (main.ts) → `nostr/ownProfile.ts` `editOwnProfile`, which does what dex's `OwnProfileModule.edit` does: the newest kind 0 from `profileRelays()` (cache bypassed, `PROFILE_LOOKUP_MAX_WAIT_MS`), the edit merged into it (unknown keys kept), refused with `profile-load-failed` when nothing loaded and the query wasn't complete, signed, and published to the group relay (`publishSigned`, AUTH retry) and the other profile relays. The new event goes into the feed's state like any kind 0, so the pill, badge, chat and card follow at once. The `@source` list in `copy-brand.mjs` includes the form's folders.
- **Language.** The shimmed next-intl serves the vendored messages in the village's language (`i18n/lang.ts`), English where a key is missing. The login SDK (`@nostr-wot/ui`) has English only: in Spanish `login/sdkSpanish.ts` swaps its texts, placeholders and labels while the modal is open. Sky's own words all come in both languages: `app/index.html`'s (header, gate, loader, rotate card, bottom bar, call bars: `data-i18n` text, `data-i18n-title` title and aria-label, `data-i18n-aria` aria-label alone, keys in `i18n/app.ts`, applied early by `boot.ts`), everything drawn inside the village (`i18n/village.ts` `vw`: prompts, toasts, cards, the chat, side, DM, zap, game, theater, relay and district panels, emote names, the call, wallet and DM error lines, the theater screen's card, the table's JOIN), the settings (`SETTINGS_WORDS`), the look editor (`CREATOR_WORDS`) and "How to play". Modules read `lang` once, at import; pure helpers that make words take an optional `VillageWords` to test Spanish. New words go in both languages (`i18n/*.test.ts` checks parity; `ui/spanish.test.ts` draws panels in Spanish). Settings' first row (Language · Idioma) remembers the choice the landing page uses (`rememberLang`) and reloads without `?lang=` (`switchLang`); `?lang=` still wins when given. Spanish is Rioplatense voseo ("Apretá E…"). Left in English on purpose: decorative signs and mock screens painted on landmarks (the nostr-wot, Liberture and openGym screens, La Crypta's neon), brand names, and seat labels published in game events.
- Wire formats must match obelisk-dex exactly (kind 9 tags, reactions, deletions, read-state kind 30078 `obelisk:readstate:v1`, games kind 2390, private messages and calls below).
- **Private messages and calls** (`nostr/dm.ts`, `voice/privateCall.ts`, `ui/dmPanel.ts`) speak obelisk-dex's protocols:
  - Chat is NIP-17: a kind 14 rumor gift-wrapped by `@nostr-wot/dm` to the recipient's inbox (10050, else 10002 read relays, else the group relay), plus a self-copy. The rumor id is the message id.
  - (Channel voice notes are dex's too: the `["voice", url, seconds]` tag on a message that is just that URL becomes `WireMessage.voiceNote` (`state.ts` `voiceNoteOf`, https only) and dex's `VoiceMessage` with its length, the author's picture and time, fitted to the chat column in `styles.css`, as dex sizes it for a wider pane.)
  - Calls are its 1:1 calls: kind 25055 control rumors (`services/call/protocol`) in expiring wraps, and the audio is its own `DmCallSession` (`services/call/session`, lazy, after `voice/node-globals`) on its default call relays.
  - Wraps are published with `authMode: 'never'`.
  - Near a connected person you're offered Message (M) / Call; the person card has both.
- **Zaps** (`wallet/`, `ui/zapSheet.ts`), as obelisk-dex sends them: `/zap [who] [amount]` (`wallet/zapCommand.ts`: the reply target, else the last other speaker; a name must fit one person) or the person card's ⚡ Zap. The wallet is a Nostr Wallet Connect link the account connects in the sheet (checked, sealed with dex's `nwc-storage`, spoken over the page hub with dex's `nwc-transport`), else WebLN for extension logins only; logging out forgets it. Paying asks the recipient's `lud16` (kept from kind 0) for an invoice with a NIP-57 zap request, then posts dex's ⚡ marker (kind 7, `amount`, `bolt11`) to the channel; it flies here at once, even if the relay refused it. If the account or relay changed while the wallet paid, no marker is posted (`ZapDraft.isCurrent`, dex's session check). In development every attempt logs dex's `[zap]` stages (no invoices, events or provider errors). Once paid, nothing may offer a retry (it would pay twice): one sheet pays at a time (Cancel and Escape wait, a new sheet is refused), and after a wallet went quiet mid-payment no sheet zaps until a reload.
- **Profiles (kind 0)** come from `profileRelays()` for everyone in `SkyState.people`: posters, mentions, the chat's components and everyone the world draws (`WorldHooks.onPersonMade`: live movers, claims, residents). `feed.ts` `profilesDue` asks for missing ones on a backoff (30 s, 1, 2, then every 5 min) and refreshes held ones every `PROFILE_REFRESH_MS` (a new account often adds its picture after its name).
- **Members and presence.** `nostr/members.ts` reads a channel's 39001/39002 and the relay's ranks (obelisk-dex's operator-published `obelisk:roles:` catalog and holders, parsed by its `relay-roles-model`; the d-tag's relay URL is tried with and without the trailing slash, re-read on a relay switch and retried when none came); `ui/memberGroups.ts` sections them like its member list. A rank is drawn as dex's `RoleBadge` (`sidePanel.ts` `roleBadge`: its colour on a tint of itself), in the member list and by the author's name in the chat (`ChatPanel` `roleOf`).
- **Forums** (`nostr/forum.ts`, obelisk-dex's publications): a group whose `parent` is a forum is one of its children. It keeps its own house, its place in the districts editor and the relay modal (a forum's child can be a whole channel, such as openGym's, not only a thread), but in the channel list it is no top row (`listRows()` in main.ts): its unread and pings count on its forum's row (`unreadIn`), and the list nests a forum's threads that have messages under its row on an L-rail, as dex's sidebar does (`ChannelRow.threads`, foldable, the fold kept in localStorage). The forum's chat lists the same threads, latest first, with no message bar (`ChatPanel.renderForum`); a thread opens in the same panel and its ‹ goes back to the forum. New threads are started from obelisk.ar for now.
- **The channel list** (`ui/sidePanel.ts`, the Channels tab) stands where the chat panel sits (`.side.at-chat`, `body.channels-open` hides the chat meanwhile), grouped and folded like obelisk-dex's sidebar: the operator's `obelisk:layout` categories in order (`ThemeStore.layout`, `ui/channelTree.ts` through dex's `applyLayout`), then the rest, headed "Uncategorized" only beside categories. Picking a channel closes the list and opens its chat in that place; the chat header's ‹ (`ChatPanel.onBack`) brings the list back. A chat author's avatar and name open their person card. Presence (`nostr/presence.ts`): online = live in the village and active within 5 min, or posted within 15 min (obelisk-dex's window); AFK = live but idle; offline otherwise. Characters show it (a green dot, a 💤 AFK tag).
- Sky-only events:
  - kind 30078 `obelisk:avatar3d:v1`: your look (avatar v2 `{look,...}`; v1 still parses), plus optional `haunts`: up to three favourite places (`world/places.ts` ids, picked in the look editor's "Favourite places", a fourth replacing the oldest; left out when empty, unknown ids dropped). Your own signed event is cached in localStorage (`obelisk-sky/avatar/<pk>`); on login or a relay switch `AvatarStore.syncOwn` shows it at once and publishes the same signed event to a relay that lacks it or has an older one. Others' looks are fetched as they appear (`AvatarStore.want`, asked again if the query didn't finish) and followed live (`AvatarStore.start`), so a change of body or clothes reaches everyone without a reload.
  - kind 30078 `obelisk-sky:themes:<relay>`: operator-only districts.
  - kind 30078 `obelisk-sky:activity:v1` (`nostr/activity.ts`): what you're doing live. Tags `op` start/stop, `spot`, NIP-40 `expiration` (90 s); content `{v,op,spot,kind,since}`. Kinds: the exercises (park and gym), `sit` (seats only), `run` (track lanes only), and on a `here:` spot an `emote:<kind>` or `ride` (remote signers only). Published 0.3 s after you sit or train, re-sent every 45 s, a stop when you get up. Two claims on one spot: the earlier `since` holds it.
  - ephemeral kind 20390 (`nostr/motion.ts`): live movement. Content `{v,t,p,mv?,run?,d?|h?,j?,e?,es?,y?,lp?,rd?}` (`y`: body yaw, or the eyes' yaw in first person; `lp`: first-person look pitch, ±0.6, tilts the remote head; standing, a 30° turn is a change worth sending) (`rd: 1`: riding a nostrich, walked at the ride speeds on a bird; getting on or off is a change worth sending, sent at the normal pace even while backing off) (`j: 1`: they just jumped; sent at take-off, at most every 400 ms, and replayed with the controller's jump physics; `e`: the emote they're playing while standing, `world/emotes.ts` kinds only, starting/stopping one is a change worth sending; `es`: when it began, their wall clock in ms, clamped to `t`): position plus a click's destination (`d`) or a key heading (`h`). Sent on a click, a turn, start/stop running or stopping; a correction every 2 s by keys / 4 s on a path; a 30 s heartbeat standing; never more than 1/s, backing off to 8 s when the relay refuses. Starting or ending an emote is sent at the normal pace even while backing off. Off with the `shareMotion` pref and for remote signers (nip46): their emotes go out as an activity instead (`here:<x*10>:<z*10>` spot, kind `emote:<kind>`), played by main.ts `playEmoteClaims` through `applyMotion`; riding goes out the same way, as kind `ride` on the `here:` spot where they got on.
- **Remote signers (NIP-46)** run on sky's own `nostr/remoteSigner.ts`, as obelisk-dex's bridge does: the login widget closes its paired signer when its modal unmounts, so sky builds a BunkerSigner on the same client key (no second `connect()`; on reload only when the pointer has a secret, then the account is checked). Every request has a deadline, the user's own requests (relay AUTH, posts) go before background ones (DM unwraps, read-state; one at a time), and a closed signer is rebuilt once. Never install the widget's `args.signer` for nip46.
- **The guest island** (`guest/`, `nostr/guest.ts`): for a visitor who isn't logged in, or a logged-in account the relay refuses (the Feed's `onAccess('refused')`). main.ts `startGuest` stops the relay feed, read-state, DMs, activity, motion and the theater and starts a `GuestFeed` through the same `handle()`: six houses (Bitcoin, Nostr dev, Art & memes, Mate & chat, Fitness, which becomes the gym, and the Campfire voice channel, an ombú with its call off) as 39000-style metas, and `script.ts` threads played as local kind 9 / kind 7 events (hashed ids, `sig: ''`) from the villagers in `npcs.json` (well-known Nostr and La Crypta accounts; their kind 0s are read from the public profile relays, never the group relay). It opens with a snapshot of the last six hours, then plays a line or reaction every so often, reshuffling and recasting the threads each loop; a villager answers what you write now and then. The lines are made-up village chat, never anyone's words, and the banner says the chats are a demo. You walk as yourself when refused, as a per-tab random guest pubkey named Guest / Invitado when logged out (`guestPubkey`). Nothing is signed or published: `isGuest()` makes `publishToGroup` / `publishSigned` return a local unsigned event (`localEvent`, ingested into the guest state, so chat, reactions and games work here), `SessionManager.sign` refuse, `guardHub` refuse every hub publish (DMs, profile edits, read-state, voice), and motion and activity aren't sent; your look is kept in localStorage only (`guest/look.ts`). Hidden there: calls (call bar, theater joins), DMs (Message/Call, the DM panel), zaps (`/zap`, ⚡ Zap, the wallet sheet), Edit profile, the bell, "Open in Obelisk". `#gate` is now a slim banner (`gate.guestLoggedOut` / `gate.guestRefused`, × hides it) with the login a tap away, and the status pill reads "LIVE · Guest island". A login, or a relay switch with access, goes back to the real feed (`startFeed` clears the flag). Villagers' `haunts` from `npcs.json` go to `World.setHaunts` on each snapshot (`applyGuestHaunts`).
- The group relay (public.obelisk.ar) only accepts events from whitelisted pubkeys after NIP-42 AUTH. Sky-only events are therefore signed with the player's own key (no throwaway session keys), and its per-pubkey rate limit is unknown: keep send rates conservative.

## World rules that are easy to break

- **Phones are played sideways.** Upright (`ui/orientation.ts` `PORTRAIT_PHONE`), a card asks to turn the phone and can go full screen and lock landscape; the manifest asks for landscape. Sideways (`(pointer: coarse) and (orientation: landscape) and (max-height: 540px)`): cards are a right side sheet, the chat, the channel list and the side panel a left column, the menu a scrolling sheet, the look creator two columns. The login modal is wide and short: choosing a method, the mark and title on the left and the four methods two by two on the right, on one screen; each step, its title in a slim left column and the step beside it (the QR beside its buttons). Its rules start with `body.sky-login` (the widget's stylesheet loads later) and follow the widget's DOM (`.nui-widget-methods`, `.nui-qr-wrap`): check them with screenshots at 844×390 and 740×360 after updating `@nostr-wot/ui`. A focused field scrolls into view as the keyboard opens (`LoginMount.tsx` `keepFieldInView`).
- **The minimap** (`ui/minimap.ts`, issue #3): the loading screen's island drawing (`islandMap`, without its made-up houses and villagers) in a round window top left (under the guest banner; hidden while the members drawer, Watch mode or, sideways on a phone, the chat or menu has the corner), with every channel's house (unread dot, "@"), the landmarks, live people and you as an arrow. Redrawn 4 times a second from main.ts `updateMinimap`, only when something moved (`minimapSig`). A click opens it big and north up with names; a house there walks you over (`onGroupClick`). Prefs `minimap` (N toggles it) and `minimapRotate` (turn with the camera).
- **Phone layout** (`(max-width: 720px)` or a touch screen up to 1024 px): the bottom bar folds into the header's menu button (`#menu-btn`, `body.menu-open`, the same `.controls` buttons with `.ctl-label`s, plus About and Log out). The prompts (`#dock`: the voice call bar first, then seat, chat, someone near; at the bottom centre on desktop) gather over Jump. The joystick is 144 px (`input.ts` `R`). The person card is a bottom sheet with a sticky close button and a grip (drag down to close); a tap on the world closes it first. Every header pill is `--pill-h` tall; the status pill is the Live ⇄ History switch.
- **Chat panel and yards.** `place` (the yard you've settled in) drives the call bar and mark-read whether or not the chat is open. The café is closed to haunts after dark, at night someone with a home still goes in as often as before, and park, track and gym haunts skip the sports-district gate. A haunt with no room (no gym, every lane taken) falls through to the usual roll: café by day, parrilla in the evening, home at night, laps / gym / park for sports homes, a seat nearby, a walk. Seats and stations are held with `reserve`/`releasePending` (`goSit`, `goLane`, `goGym`, `goPark`).
- **Characters.** When the world places someone (seat, station), call `resetDrive()` so a stale run or jump state doesn't override the pose. Seats put the person `SIT_SEAT_HEIGHT` below the seat. The badge and speech bubbles follow the head bone.
- **Live activities and movement.** People steered from another browser are *pinned* (`World.pinned`): `idleLife` and the Director's walks, conversations and despawns leave them alone.
  - A live claim (`World.syncClaims`, from `ActivityStore.live`) runs the person to the spot, or fades them across if far or pathless, then sits or trains them. An NPC on the spot is evicted. A claim beats movement.
  - Live movement (`World.applyMotion`) walks them at the player controller's speeds (`Character.pace`), fades them across when more than 4 m off, and goes stale after 75 s (`World.expireMotion`): they return to local life, or leave if they only appeared to move.
  - Spot ids are `station:<index>`, `seat:<x*10>:<z*10>` and `lane:<0..2>`, so moving a bench or reordering `CALISTHENICS_STATIONS` changes ids between builds. Gym machines are appended to `stations` after the park's, so park ids don't move when a gym appears.
  - NPC seat and station reservations go through `reserve`/`releasePending`, never `taken = 'pending:…'` directly.
- **Clothes and skin colour** (`people/people.ts` `tintable`): a garment's texture brightness is divided by its own mean linear luminance (`garmentLuma`), so it shows the chosen colour itself. Without that, trousers (mean ≈ 0.01) render black. Faces use the same dye as the hands at the skin tone, keeping a little of the painted texture (`SKIN_DYE`). Skin textures load with the look (`loadLook`) so they can be measured.
- **Lighting:** the hemisphere fill is what faces, pets' bellies and building sides turned from the sun get. `world/sky.test.ts` keeps day, dusk and night fill above a floor; don't drop it to darken a mood.
- **Exercise clips** are generated per body and grip height; hands are posed per grip (`OVER_BAR`, `ON_BAR`, `ON_PARALLEL`, `FLAT`) and the grip anchor is inside the curled fingers. Keep `exercises.test.ts` passing when changing poses.
- **Assets.** Cloudflare caches `/models/*` and `/assets/*` as immutable for a year: a changed file under the same URL keeps serving the old one (add `?v=`). The server's CSP must keep `blob:` in `connect-src` and `'wasm-unsafe-eval'` in `script-src`, or GLB textures and meshopt fail and bodies don't render; `frame-src` allows only YouTube (LABITCONF's stage) and totemcillo (the totem monitor's focus, `TOTEM_ORIGIN`; `server/index.test.ts` checks they match).
- **Performance.** `__sky.perf()` (any build) reports one frame's draw calls and triangles (every post pass), lights on and the quality level. Keep it from regressing:
  - Channel houses are merged after building (`world/merge.ts` `mergeStatic`, one mesh per material); the roof (`name: 'roof'`) and `windows` stay separate. Anything you add to a house that moves, hides or changes on its own must be kept out of the merge too.
  - Landmarks and the gym are merged too: `findDynamic` runs their own hooks (update at a few times, night, door, inside, pulse) and keeps out every mesh that moved, hid, changed its shadow flag or geometry. Hooks put things back (a door opened then closed), so the poke calls `mark()` after each hook; without it doors get merged away. Something that only World code moves (not the landmark's own hooks) must be named and kept explicitly.
  - Phones: shadows at most 1024 and refreshed every 2nd–3rd frame; on "low" and still slow, "auto" renders fewer pixels (`lowScaleStep`, down to 60 %).
  - Point and spot lights are budgeted (`world/lightBudget.ts`): only the nearest few are visible, with constant counts so shaders don't recompile. A new lamp is picked up on the frame it joins the scene (`LightScan`: anything added to or removed from the scene or the World's roots marks it; a rescan every 3 s besides); don't toggle `visible` on lights yourself. Every street lamp (`World.lantern`: round the plaza, at the park's corners, `CALISTHENICS_LAMPS`) has its own light, and they switch on together from early dusk (`lampLevel`), never half-lit.
  - People out of view are hidden and not posed (`Character.offscreen`). "Auto" quality starts by device and steps both ways (`world/quality.ts`); grass follows the effective level (`Post.onLevel`).
- **The frame loop never dies.** `main.ts` `loop` asks for the next frame first and catches a frame's throw (logged once per kind); `World.frame` always renders in a `finally`, after `Cameraman.guard` puts a non-finite camera back. A non-finite player position steps back to the last good one. A lost WebGL context (phones short of memory) is asked back (`webglcontextlost` → `preventDefault`), drawing pauses, and on restore `Post.stepDown` drops a quality level for good; after 5 s without it a toast offers a reload.
- **Ambient occlusion and the blur.** GTAO's normal pass would draw sprites and additive glows as opaque squares: `world/aoMask.ts` hides them from it. The tilt-shift is a jittered nine-tap blur; sparse taps turned bright points into dot grids.
- **Black flashes.** Resizing the canvas clears it, so the quality ladder (`Post.render`, `pendingLevel`) and window resizes (`World.frame`, `needsResize`) apply at the start of a frame, never after drawing. NaN/∞ from a glint or the AO is cut before the blurs (`SafeColor` after the scene and after GTAO) and in `Grade`.
- **Water shader:** GLSL `smoothstep(a, b, x)` needs a < b.

## Roadmap

`docs/ROADMAP.md` lists the obelisk-dex features sky still lacks or only partly has, with the next five to port and the plan for social notes (re-hosting dex's note components and publishing through the outbox). When you port one, update that file in the same change.

## Testing

Every change comes with tests next to the code (`*.test.ts`, `*.test.tsx`), and `npx tsc -p tsconfig.json` plus `npm test` must pass before a deploy. Visual changes also get a headless screenshot check. Use the playwright in `/root/obelisk-dex/node_modules` with `--use-angle=swiftshader`. It is slow, so allow minutes. The dev build exposes `window.__sky` (world, player, chat, controller, activity, motion) and `__skyDevLogin(hex)` for a throwaway key. Never log in with a real key in tests, and never post to a relay from tests. A logged-in test page shares movement by default: set `shareMotion: false` in the `obelisk-sky/prefs` localStorage entry first. To test remote people, feed signed events to `__sky.activity().ingest` / `__sky.motion().ingest` instead of publishing. Software rendering runs at about 1 fps (world time crawls), so poll for state rather than sleeping a fixed time; don't edit source files while a headless run is going (Vite reloads the page mid-run); and kill leftover `headless_shell` processes after a timed-out run.

## Secrets and hygiene

- `.env` holds the retired v1 bot key. Never commit it, never print it, never use it in the client. It is due for deletion once the key is un-whitelisted.
- `_dl/` (about 1 GB of source packs), `node_modules/`, `dist/` and the reference photos are not source; keep them out of version control (`.gitignore`).
- Keep files focused; prefer the existing helpers (`dist`, `rng`, `fbm2`, `model()`, `buildPerson`, `landmarkToWorld`) over new ones.
